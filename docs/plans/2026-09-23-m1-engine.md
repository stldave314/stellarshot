# M1: Engine, implementation plan

**Goal:** Replace the scattered rustic 0.2 calls with one engine module on rustic 0.13. Reads run on blocking threads, and writes run in a cancellable child process with progress. A lock is shared by every process that writes to a repository, and errors are typed.

**Architecture:**
- The crate splits into a library (`src/lib.rs`) and a thin binary (`src/main.rs`), so integration tests can drive the engine and the child process directly.
- `src/engine/` is the only code that imports `rustic_core`. It's synchronous and returns plain types.
- `src/runner.rs` implements `stellarshot --run`: it reads a JSON job from stdin, writes JSON-line events to stdout, and exits 0 on success, 1 on a reported error.
- The window spawns that child for backups and reads its events as a stream.

**Tech stack:** rustic_core 0.13 and rustic_backend 0.7 (default features off, since the local backend needs none; rclone is added in M3), serde_json, std `File::try_lock` (stable since Rust 1.89), and edition 2024.

**Spec:** `docs/specs/2026-09-23-stellarshot-roadmap-design.md` §5 and §8

## Global constraints

The M0 constraints still apply. In addition:
- No `rustic_core` type appears in any public signature outside `src/engine/`.
- Passwords reach the child process **on stdin only**, never in argv or the environment, because both are readable from `/proc` by other processes of the same user.
- **Deviation from the spec (§5.3):** the lock and progress files are keyed by the repository **location**, not by profile ID. Two profiles pointing at the same repository must share one lock, and profile IDs only arrive in M2. The key is the first 16 hex characters of the SHA-256 of the location string.

## Review focus

1. **Exclusions.** An excluded folder inside an included folder must be absent from the snapshot, and an exclude pattern must apply at any depth. Test: `excluded_folder_is_not_in_the_snapshot`.
2. **A backup killed partway through.** The repository must pass `check` and accept the next backup. Test: `killed_backup_leaves_a_sound_repository`.
3. **Two writers at once.** The second must report `Locked` and must not write. Test: `second_writer_reports_locked`.
4. **The wrong password.** It must map to `WrongPassword`, never to a generic error. Tests: `wrong_password_is_reported_as_such` (engine) and the runner's error event.
5. **Awkward file names and types.** Spaces, unicode, `%`, symlinks, empty folders, and a mode-0600 file must survive a round trip. Test: `round_trip_preserves_tree`.

### Task 2: Engine types and errors (`src/engine/{mod,error,secret}.rs`)

```rust
pub struct Secret(String);            // Debug prints "Secret(***)"
pub struct Location(PathBuf);         // M1: local folders; M3 turns this into Destination
pub enum EngineError { WrongPassword, NotARepository(String), AlreadyExists(String),
    LocationNotEmpty(PathBuf), DestinationUnavailable(String), Locked, Canceled,
    RepositoryDamaged(String), Io(String), Internal(String) }
pub struct ErrorReport { pub kind: ErrorKindTag, pub detail: String }  // serde, crosses the process boundary
```

`From<RusticError>`: `is_incorrect_password()` → `WrongPassword`, and `ErrorKind::Backend | InputOutput` → `DestinationUnavailable`. Anything else becomes `Internal` with the error's display text.

### Task 3: Repository operations (`src/engine/repo.rs`, `snapshots.rs`, `backup.rs`, `restore.rs`, `maintenance.rs`)

```rust
pub fn init(location: &Location, secret: &Secret) -> Result<Repo, EngineError>;   // refuses NotEmpty (M0 rule kept)
pub fn open(location: &Location, secret: &Secret) -> Result<Repo, EngineError>;
impl Repo {
    pub fn snapshots(&self) -> Result<Vec<SnapshotSummary>, EngineError>;
    pub fn backup(self, request: &BackupRequest, progress: &dyn ProgressSink) -> Result<BackupReport, EngineError>;
    pub fn restore_all(self, snapshot: &str, destination: &Path, progress: &dyn ProgressSink) -> Result<(), EngineError>;
    pub fn delete_snapshots(&self, ids: &[String]) -> Result<(), EngineError>;
    pub fn check(self) -> Result<(), EngineError>;   // RepositoryDamaged on findings
}
pub struct BackupRequest { pub sources: Vec<PathBuf>, pub excludes: Vec<PathBuf>,
    pub exclude_patterns: Vec<String>, pub one_file_system: bool }
pub struct SnapshotSummary { pub id: String, pub time: i64 /* unix seconds */, pub paths: Vec<String>,
    pub files_new: u64, pub files_changed: u64, pub data_added: u64, pub total_bytes: u64 }
```

**Tests (`src/engine/tests.rs`, real repositories in temp dirs):** `round_trip_preserves_tree`, `excluded_folder_is_not_in_the_snapshot`, `exclude_pattern_applies_at_any_depth`, `wrong_password_is_reported_as_such`, `open_non_repository_is_not_a_repository`, `second_backup_is_incremental` (`files_unmodified > 0`, small `data_added`), `delete_snapshot_removes_it`, `check_passes_on_a_fresh_repository`.

### Task 4: Progress (`src/engine/progress.rs`)

- A `ProgressSink` trait: `fn update(&self, event: ProgressEvent)`.
- A `ProgressEvent { phase: String, done: u64, total: Option<u64>, bytes: bool }`, serde.
- `SinkBars<S>` implements rustic's `ProgressBars`. Each handle forwards `set_length`/`inc`/`set_title`, throttled to `PROGRESS_INTERVAL` (constants), with the final value always sent on `finish()`.

**Test:** `throttle_sends_first_and_final`. 1,000 rapid `inc(1)` calls produce far fewer events, and the last one has `done == 1000`.

### Task 5: Lock and runner (`src/engine/lock.rs`, `src/runner.rs`)

- `lock::acquire(location) -> Result<WriteLock, EngineError>`. It takes a non-blocking exclusive `try_lock` on `$XDG_RUNTIME_DIR/stellarshot/<key>.lock` (falling back to `std::env::temp_dir()`). `WouldBlock` → `Locked`, and the lock is released on drop.
- `runner::main()`:
  - Parses `--run <backup|restore|check|delete-snapshots>`.
  - Reads one JSON `Job` from stdin: `{ repository, password, request?, snapshot?, destination?, ids? }`.
  - Takes the lock for writes.
  - Emits `{"event":"progress",...}` lines and ends with `{"event":"done","report":...}` or `{"event":"error","kind":...,"detail":...}`.
- **Integration tests (`tests/runner.rs`, via `env!("CARGO_BIN_EXE_stellarshot")`):**
  - `runner_backs_up_and_reports_done`
  - `runner_reports_wrong_password`
  - `second_writer_reports_locked` (the test holds the lock, then runs the child)
  - `killed_backup_leaves_a_sound_repository` (about 40 MB of incompressible files, SIGKILL after the first progress event, then `check` passes and a fresh backup succeeds)

### Task 6: The window uses the engine

- Remove `src/backup/{init,snapshot,restore}.rs`. `location.rs` moves to `src/engine/location.rs` unchanged, with its tests.
- Listing snapshots goes through `spawn_blocking(engine::open(..).snapshots())`.
- Create snapshot spawns `stellarshot --run backup` (`std::env::current_exe()`) with the job on stdin. `Task::run` turns the stdout lines into `Message::BackupProgress` / `BackupFinished` / `BackupFailed`.
- The content view shows a progress bar with **Cancel**, and cancel kills the child. The window never blocks.
- Delete snapshot and create repository go through the engine on `spawn_blocking`.
- Errors map to localized messages per kind (`WrongPassword`, `Locked`, `DestinationUnavailable`, `LocationNotEmpty`, `NotARepository`, `Canceled`, and `Internal` with its details), in every locale.
